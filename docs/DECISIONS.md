# Исходные архитектурные решения

Это принятый базовый план, не протокол выполненных экспериментов. Изменение решения оформляется новым ADR с причиной, альтернативами и влиянием на этапы; исходная запись сохраняется.

## ADR-001 — Функция компонента важнее красивой геометрии

Цель: проектировать и измерять поведение. В библиотеке хранится функция, среда, рабочий диапазон и evidence. Следствие: визуализация не закрывает научный этап.

## ADR-002 — DNA Nanomechanics как первая специализация

Выбран путь E1 → шарнир E2 → проверка ИИ E3. Ранее обсуждённый 2D Materials & Interfaces Lab сохранён как последующее направление, а не удалён. Причина: более прямой первый шаг к механическим компонентам. Выбор модели остаётся условным до NL0 и контрольного расчёта.

## ADR-003 — Повторно использовать научные движки

Не писать собственный универсальный симулятор. Предпочтительный первый движок oxDNA; интерфейсы проектирования и анализа выбираются из существующей экосистемы. API и лицензии проверяются до включения зависимостей.

## ADR-004 — Сначала расчёт без ИИ

NL1–NL3 создают проверяемую лабораторию. ИИ добавляется к уже работающему циклу в NL4. Это позволяет отличить ошибку физики, интеграции и научного планирования.

## ADR-005 — AiiDA как основа provenance

Использовать существующее управление вычислительными процессами. Прототипировать через aiida-shell, если подходит. Первый smoke-сценарий может быть локальным до интеграции; каноническая научная история не должна жить только в stdout или чате.

## ADR-006 — Один исследовательский агент и независимые проверки

Один основной агент; отдельный численный оптимизатор и непривилегированный анализ. Множество согласных LLM не считается независимой физической проверкой. Разработчик кода и оператор исследования имеют разные права.

## ADR-007 — Никаких заранее выдуманных численных порогов

Целевой угол, точность, число шагов и достаточность выборки устанавливаются из выбранного эталона, пилота и научной постановки. Критерии замораживаются до оцениваемой кампании. Последующее изменение создаёт новую версию.

## ADR-008 — Сначала доступный локальный путь

Не делать GitHub Actions, облачную подписку, GPU определённой модели или собственную лабораторию обязательными до оценки задачи. Большие опыты запускаются только с явным бюджетом; создание workflow не означает разрешение на вычислительные расходы.

## ADR-009 — Публикация исходного документального фундамента

Владелец запросил заполнить новый пустой репозиторий. Первичная публикация документации допускается в main. Последующие кодовые изменения — ограниченные ветки и PR с проверками; force-push в main не допускается.

## ADR-010 — Открытость без самовольного лицензирования

Открытая разработка — цель. Выбор лицензии собственного кода/документов требует решения владельца. Лицензии сторонних программ, весов и данных учитываются раздельно. До решения репозиторий нельзя рекламировать как уже лицензированный для любого повторного использования.
