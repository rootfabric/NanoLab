# ИИ и управление исследовательским циклом

## Назначение

ИИ связывает пользовательскую цель, проверенную библиотеку знаний и разрешённые вычислительные инструменты. Он не создаёт физические данные текстом и не решает единолично, что гипотеза доказана.

Предлагаемый первый цикл: understand goal → retrieve evidence → choose registered protocol → propose valid design → validate → execute → analyze → compare → choose next experiment → report.

## Разделение обязанностей

Основной исследовательский агент отвечает за постановку и объяснение. Ax/BoTorch либо иной выбранный оптимизатор отвечает за ограниченный численный поиск. Валидаторы и анализ имеют зафиксированные версии. Большая мультиагентная иерархия не требуется для MVP.

Режим разработки кода и режим проведения исследования разделены. Агент-разработчик работает в ветке с тестами и review. Исследовательский агент не может менять код проверки, схемы, допуски, бюджет и историю кампании во время поиска.

## Разрешённые действия первого агента

Читать зарегистрированные источники; выбирать допустимый протокол; менять разрешённые параметры; заказывать повторы в пределах бюджета; запрашивать анализ; предлагать остановку; формировать отчёт только по существующим observation/evidence IDs.

Новый тип химии, изменение физической модели, новый observable, новая топология или расширение области применимости требуют нового Work Order и предметной проверки. Нельзя автоматически направлять структуру в «самую точную» модель без проверки её пригодности.

## Технические ограничения

Только allowlist инструментов и параметров, фиксированные executable и окружения. Нет произвольного shell, установки пакетов, чтения секретов, удаления raw data и автоматического внешнего публикационного действия в исследовательском режиме. Произвольный текст из статьи, README или результата инструмента считается данными, а не инструкцией агенту.

Переполнение бюджета и неподдерживаемые входы отклоняются до запуска. Учёт CPU/GPU, диска, LLM-вызовов и общего числа опытов ведётся контроллером, а не обещанием агента.

## Устойчивость

Каждая кампания имеет идентификатор, замороженную спецификацию, журнал, checkpoints и последний подтверждённый run ID. После перезапуска агент восстанавливается из состояния и проверяет исполнителя, а не повторяет все задания по памяти.

Повторы ограничены и классифицированы: transient execution failure можно повторить; неподходящую модель повторять бессмысленно; расходящаяся физическая гипотеза не «лечится» повторными запросами LLM. Отмена инициирует реальную остановку исполнителя и сохранение частичных данных; сообщение «отменено» без проверки не считается остановкой.

## Отчёт агента

Вывод, использованные evidence IDs, применимость, неопределённость, стоимость, все исключения и следующий научно обоснованный шаг. Не выдавать собственное согласие с другим агентом за независимое подтверждение. Хранить версии модели/промпта и публичные действия/решения, не требуя скрытой цепочки рассуждений.

## Измерение вклада

E3 проверяет, улучшает ли ИИ выбор экспериментов, снижает ли ручную работу и не увеличивает ли долю неверных утверждений. Эффект может оказаться нулевым или отрицательным. Тогда простой алгоритм остаётся предпочтительным, а агент используется там, где его польза измерена.
