2. **Preparation** (go/no-go, не наука): fixture из сырых blob'ов pinned commit `00dc7fb9a25bbd8cadbc7503ee2b9f38983c6591` (`git cat-file blob`, SHA-256 4/4 против пинов §2.2 R1 перед каждым прогоном); engine — reuse зафиксированной сборки кампании E1-R1 (бит-в-бит бинарь `ffc80b1a…`, 3375976 B, Release/DOUBLE=ON/CUDA=OFF/MPI=OFF/NATIVE=ON) с верификацией SHA-256/размера/флагов и commit-строки лога перед прогонами; fallback — пересборка по `ENGINE_ENVIRONMENT_R1` §3 с записью новых SHA-256. Reuse бит-в-бит сборки S001 устраняет пересборку как конфаунд между точками confirmatory set.
3. **Статистика** (frozen, менять запрещено): confirmatory set = `S001 + C001–C003` (4 точки, все значения публикуются полностью); mean и выборочное SD (n−1, как в пилоте E1-PROTO-R2 §1); per-replica IN_BAND/OUT_OF_BAND; агрегат по §9 R1: campaign-критерий выполнен тогда и только тогда, когда T1 = PASS **и** все T2-реплики в полосе. Пост-хок исключения запрещены; полоса/оракул/колонка/усреднение не меняются (§5.3 R1). Отрицательный результат (хотя бы одна реплика вне полосы) сохраняется как NOT_SUPPORTED-путь, повтор «до успеха» запрещён.
4. **Analysis**: `analyze_energy.sh` (тот же инструмент, что в E1-R1, байт-в-бит) на published `energy.dat` каждого прогона; целостность §5.2 (1001 строка = 1 initial + 1000 prints, 10 конфигураций, NaN/Inf = 0, N=16/molecules=2, engine facts); диагностическая задача NL2-002 по §4 R2 — между-репликационный разброс (best-effort, не gate).
5. **Archive**: контрактная обвязка каждого прогона (уникальный run ID, `/usr/bin/time -v`, массив-манифесты с 40-hex `subject_sha`/`producer_run_id`/`producer_command`, события с `experiment_id`, терминал последним — уроки ремонта NL1-002 R2 и E0 NL2-001), summary, evidence-map, handoff.
