# Work Order NL4-003 — Пользовательский MVP (clean-room прогон)

Статус: READY (Author: Director 2026-09-12; frontier NL4; это последний WO стадии NL4 — acceptance NL4 = MVP COMPLETE). Ветка: `work/nl4-003-mvp-r1` от свежего main.

## Цель

Собрать **пользовательский путь** одним CLI и доказать его **clean-room прогоном**: пользовательская цель (JSON) → bounded experiment → реальные прогоны → выбор → подтверждение свежей репликой → **отчёт** (карточка-стиль: candidate, распределение угла, confidence, provenance, limitations; «поиск не удался» — поддерживаемый исход).

## Состав

1. **`scripts/nl4/mvp.py`** (CLI): вход `--goal user-goal.json` → (`{"target_angle": 90, "max_simulations": 3, "steps": 50000, "revalidation_runs": 1}`); стратегия **informed-greedy** (детерминированная, scripted: старт с published-ближайшего варианта из series-summary, затем 2 alternatives; БЕЗ LLM); цикл через `Controller + RealExecutorAdapter` (реальные прогоны); выбор best; **re-validation**: 1 свежий seed (206024) на best; финальный заявляемый score = по re-validation (анти-bias правило NL4-002 наследуется); отчёт `mvp-report.md` + canonical JSON: goal, все runs (IDs, digests), распределение угла, gates, chosen candidate + revalidated score, confidence (кадры/CI), provenance (pinned commit, engine, дайджесты), limitations (дискретное пространство, coarse-grained, конвенция [0,180], 74b gap), reproduction instructions, verdict FOUND/NOT_FOUND (неуспех = нормальный исход при невыполнимых гейтах).
2. **Clean-room верификация (обязательная, это главный deliverable)**: свежий `git clone` репозитория в новый каталог (НЕ worktree), пустые run-каталоги, прогон MVP из clean-копии на цели `{"target_angle": 90, ...}`; никаких ручных правок артефактов; отчёт и evidence публикуются как есть (включая если NOT_FOUND/выход за бюджет).
3. Records: START до substantive; events с уникальными timestamps; END_EXECUTION (манифесты ранов); END_ANALYSIS (report + verdict); HANDOFF; SESSION_LOG append.
