# Work Order NL0-001 — Выбор воспроизводимого эталона

Статус: READY, не запущен. Родитель: NL0. Репозиторий: rootfabric/NanoLab. Предлагаемая ветка: `work/nl0-001-reference-selection-r1`.

## Цель

Выбрать небольшой физический пример для E1 и обоснованный кандидат семейства шарниров для E2, чтобы следующая работа опиралась на реальные доступные данные, а не на пересказ статьи.

## Прочитать

[ROADMAP](../ROADMAP.md), [E1](../experiments/E1_REFERENCE_REPRODUCTION.md), [E2](../experiments/E2_HINGE_COMPONENT.md), [SOURCES](../research/SOURCES.md), [SCIENTIFIC_METHOD](../SCIENTIFIC_METHOD.md) и корневой AGENTS.md.

## Разрешённая область

Первичные статьи, upstream-примеры, официальные базы конструкций и их метаданные; проверка наличия файлов и условий; документирование результатов. Допустима небольшая загрузка разрешённых файлов для inspection с сохранением checksum. Не публиковать чужие бинарные/научные данные без проверки прав.

Не требуется установка большого стека, запуск физической кампании, обучение модели, создание пользовательского UI или новый оркестратор. Не выполнять E4 и не пытаться сразу построить мотор.

## Работа

Проверить до трёх кандидатов небольшого E1. Для каждого записать название и постоянный идентификатор источника, конкретные доступные input-файлы, топологию/модельные предположения, условия, observable, reference output, права и недостающие сведения. Для E2 начать с S08, но не считать его автоматически пригодным до проверки файлов.

Выбрать один E1 по полноте, размеру и воспроизводимости, а не по зрелищности. Для E2 выдать приоритетный кандидат и ограничения. При недоступности всех рассмотренных входов перечислить реальные попытки и предложить следующий ограниченный путь; не заменять источник вымышленной конструкцией.

## Ожидаемые артефакты

Создать `docs/research/REFERENCE_SELECTION.md` с сравнением и решением; `docs/research/INPUT_AVAILABILITY.md` с фактическими источниками/файлами/пробелами; обновить SOURCES и журнал. Эти два файла являются будущими результатами задания, а не уже существующими документами.

Не выдумывать точные scientific tolerances: дать данные для NL0-003. Не назначать лицензию NanoLab: вопросы передаются NL0-002.

## Приёмка

Другой агент может по отчёту получить тот же исходный файл или увидеть точный documented access blocker; checksum вычислен для действительно полученного файла; источник соответствует заявленной конструкции; явно отделены REPORTED, ASSUMED и UNKNOWN. Есть одно конкретное следующее действие для NL0-002/003.

Завершить ограниченную работу, commit/PR, проверку опубликованных файлов и журнал. Не отмечать NL0 целиком закрытым: это только первое из трёх заданий стадии.
