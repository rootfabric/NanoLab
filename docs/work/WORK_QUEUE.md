## Как брать задание

Статус READY означает готовность планирования, не разрешение на неограниченные расходы. Из одного Work ID при необходимости создаётся небольшой дочерний WO с точным scope; не дробить работу до бесконечного административного процесса. Все дочерние задания ссылаются на родителя.

Перед стартом проверить зависимости в actual state. После задания обновить журнал и evidence. Только после принятого результата изменить статус; commit без приёмки — IMPLEMENTED, не автоматически ACCEPTED.

## Правила параллельности

Научный runtime сохраняет одну основную вертикаль. Параллельно с NL5 разрешена bounded capability-линия `INFRA2 → INFRA3`, а также независимые release/reproduction review-задачи без конфликта scientific subject. INFRA не закрывает `NL*` автоматически. Параллельные агенты не меняют одни контракты, не запускают одну кампанию дважды и не создают альтернативную систему статусов.

## Политика неизвестных значений

Неизвестные или ещё не принятые значения не подставляются произвольно. Лицензия собственных материалов NanoLab ВЫБРАНА владельцем (D2, 2026-09-18: код Apache-2.0; документация + derived data CC-BY-4.0) — открытое лицензионное решение закрыто. `74b` остаётся `NOT_MEASURED` до отдельной arm-manifest-v2 ревизии и может быть честно выпущен как known gap. Пороговые/протокольные значения E5 и E3-R2 должны быть заморожены отдельными будущими Work Orders до confirmatory data; E4/E6 не активируются автоматически.
