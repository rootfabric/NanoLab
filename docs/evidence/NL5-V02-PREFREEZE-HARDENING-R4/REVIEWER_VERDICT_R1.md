## 2. Blocking findings

### M-1 — The declared dispatch entrypoint accepts a NOT_FROZEN protocol

Severity: **MAJOR / BLOCKING**

The candidate and Work Order require:

```text
HG-B owner approval
→ Director FREEZE record
→ fresh review/verify of frozen protocol
→ R2 ACTIVE
→ scientific dispatch
```

However `scripts/nl5/repro_v02_freeze_contract.py::build_execution_plan()` only requires the structural contract gate to PASS. It does **not** require:

- `scientific_subject.freeze_status == "FROZEN"`;
- a Director freeze record / exact frozen subject pin;
- HG-B approval evidence;
- R2 ACTIVE evidence for the author/external execution path.

The committed R4 contract itself contains `"freeze_status": "NOT_FROZEN"` and the positive tests explicitly require this pre-data package to produce a dispatch plan and CLI exit 0:

```text
CleanPackagePositiveTest.test_dispatch_plan_built_only_from_valid_package
CleanPackagePositiveTest.test_cli_gate_exit_zero_and_plan_exit_zero
```

Thus the implementation proves the opposite of the protocol invariant: the object named `nanolab_v02_dispatch_execution_plan` can be produced before freeze.

This is not merely naming. The module docstring calls `build_execution_plan` “THE dispatch entrypoint” and states that there is no path to a plan without the full gate. The current full gate treats `NOT_FROZEN` as a valid state and therefore cannot serve as the final execution authorization gate.

**Required repair:** separate at least `PREFREEZE_VALIDATION_PASS` from `DISPATCH_READY`. A pre-freeze candidate may pass internal consistency checks, but the dispatch authority must reject it until immutable freeze authority exists. The final dispatch-ready gate must machine-bind frozen status, Director freeze record, owner HG-B decision, the required frozen-subject review/verify state, and R2 ACTIVE / authorized executors for both legs (or an unbypassable separate launcher gate).

Add negative tests proving that the current PRE-DATA / NOT FROZEN package cannot yield a scientific dispatch plan.

### M-2 — Replacement pools are not bit-exactly regenerated by the authoritative gate

Severity: **MAJOR / BLOCKING**

R4 correctly generates replacement pools after the real consumed cursor. But the authoritative validator does not prove that the published replacement identities are the deterministic stream it claims.

`_validate_replacement()` checks pool length, int32 values, disjointness, start index and cursor arithmetic. It does **not** re-derive every replacement seed from `anchor + variant + candidate index + recorded skips` and does not validate the content/seed/reason of replacement `skipped` entries.

`_validate_record_binding()` performs bit-exact replay only for the confirmatory stream. It then checks that record replacement pools equal contract replacement pools, which only proves that two editable documents agree with each other.

The logical `record_sha256` intentionally preserves the R3 recipe and excludes replacement pools. Therefore a coordinated hand edit of contract + R4 seed record + file SHA can create an arbitrary replacement pool that still satisfies the current internal gate, provided uniqueness/range/quota fields remain consistent.

**Required repair:** for every variant, independently replay the replacement stream from `start_index`, including exact skipped candidate indices, and compare the resulting pool bit-for-bit with the published pool. Validate each replacement skip as `index + derived seed + reason = SEED_COLLISION_TREE`. Add a dedicated replacement-pool/full-R4 digest. Add a negative test that changes one replacement identity while keeping contract and record mutually consistent and requires rejection.

### M-3 — Collision-skip legitimacy is not part of the authoritative freeze gate

Severity: **MAJOR / BLOCKING**

The pinned-tree scanner itself is materially improved. The problem is that its result is not mechanically bound into the freeze/dispatch decision.

The current gate verifies that `exclusion_tree_pin` has SHA syntax and replays confirmatory identities using the **recorded skip indices**, but it accepts those skip indices as given. It does not prove that each recorded `SEED_COLLISION_TREE` skip actually collides in the pinned tree.

The committed `r4-collision-scan-R4.json` scans the **176 accepted fresh identities** (148 confirmatory + 28 replacement) and proves they are clean. It does not establish that all skipped candidate identities were legitimate collisions.

A coordinated edit can therefore mark arbitrary early candidate indices as “skipped”, advance the deterministic stream, and still pass confirmatory replay. This is an anti-bias integrity gap.

**Required repair:** at freeze validation, re-run the immutable pinned-tree scan or bind an independently generated scan manifest whose digest is part of the authoritative contract. Every accepted identity must be clean outside the exact allowlist, and every recorded collision skip must have a real non-allowlisted hit in the pinned tree with the recorded seed matching deterministic derivation. Scan errors/missing objects fail closed. Add a negative test with an artificial skip of a non-colliding identity.

### M-4 — ReplacementLedger does not enforce pair-level state and permits repeated consumption for one failure

Severity: **MAJOR / BLOCKING for F3 claim**

The Work Order requires two legs of a pair to be linked and replacement to invalidate/re-run the pair when either side fails.

Current `ReplacementLedger` stores independent attempts with `attempt_id, variant, leg, outcome` but has no pair identity / seed identity / counterpart relationship. It cannot mechanically prove that both legs belong to the same pair or that both are re-executed after a replacement.

Additionally, `request_replacement(variant, failed_attempt_id)` does not mark the failed attempt as already consumed. Calling it repeatedly with the same `FAILED_TECHNICAL` attempt consumes multiple replacement identities and pair quota.

**Required repair:** use a pair-level append-only state machine binding pair/seed identity, author attempt, external attempt, technical outcome of each leg, pair terminal state and replacement assignment. One failed pair may receive at most one replacement assignment; repeat requests must fail; a replacement must explicitly schedule both legs with the new frozen identity. Add negative tests for duplicate replacement request, missing counterpart, mismatched pair identity and one-leg-only replacement.

## 3. Scientific/protocol wording finding

### m-1 — Equivalence is described as “indistinguishability from zero”

Severity: **MINOR, MUST FIX BEFORE FREEZE**

R4 correctly narrows scope to the median paired shift. However `3 says PASS means “неотличимость медианного сдвига от нуля” in the chosen scale. That is not the correct interpretation of an equivalence/TOST-style decision. A shift can be statistically distinguishable from zero and still be practically equivalent if the entire CI lies inside the predeclared equivalence margins.

Use wording such as: “the CI for the median paired shift lies wholly inside the predeclared equivalence interval (−δ·s_eff, +δ·s_eff)” rather than “indistinguishable from zero”.

Also consider standard TOST hypothesis labels (null = non-equivalence, alternative = equivalence), or explicitly state that the document uses non-standard H0/H1 labels.
