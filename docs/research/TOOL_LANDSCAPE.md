# Инструменты и стратегия повторного использования

Цель — собрать проверяемую лабораторию, не переписать существующую науку. Документ сохраняет круг проектов из предварительного обсуждения. **Только первая группа имеет проверку основных описаний при инициализации.** Остальные — agenda для будущего технического исследования, без подтверждения текущих лицензий, цен, API и совместимости.

## Первая группа: кандидаты MVP

| Инструмент | Планируемая роль | Что ещё требуется |
|---|---|---|
| scadnano | Параметризованный дизайн и экспорт | Проверить выбранную топологию, версии и права |
| oxDNA / oxpy | Специализированная физика и Python-управление | Зафиксировать модель, собрать и воспроизвести эталон |
| oxDNA_analysis_tools | Базовые наблюдения траекторий | Проверить определения и независимые тесты анализа |
| oxView | Просмотр конструкций и результатов | Связать изображения с реальными run IDs |
| PyMBAR | Анализ коррелированных выборок | Проверить adequacy на выбранной задаче |
| AiiDA | Исполнение и provenance | Локальный smoke и научный workflow |
| aiida-shell | Тонкое подключение executable | Адаптер, ограничения, парсинг и обработка ошибок |
| Ax/BoTorch | Выбор следующего опыта | Бюджет, ограничения и E3 против простых baselines |
| NANOBASE | Поиск исходных конструкций | Доступность конкретных файлов и лицензии |

Источники: [S01–S13](SOURCES.md). Все статусы интеграции: NOT_IMPLEMENTED. Предпочтение библиотеки не является зависимостью, уже установленной в репозитории.

NL0-002 проверил первичные лицензии первой группы: scadnano — MIT; oxDNA/oxpy и analysis tools — GPL-3.0; oxView — GPL-3.0; PyMBAR — MIT; AiiDA — MIT; aiida-shell — MIT; Ax и BoTorch — MIT (planned, E3). GPL-компоненты подключаются как отдельно устанавливаемые зависимости, не vendored-код. Полная матрица с evidence и режимами доступа: [DEPENDENCY_LICENSE_MATRIX.md](DEPENDENCY_LICENSE_MATRIX.md). NANOBASE — per-record права UNKNOWN, режим `REFERENCE_ONLY`.

## Сохранённые кандидаты следующих специализаций

| Направление | Проекты для проверки | Исследовательский вопрос |
|---|---|---|
| Атомистические представления | ASE, pymatgen | Какой минимальный контракт нужен второй специализации? |
| Классическая/укрупнённая динамика | LAMMPS, OpenMM, GROMACS | Какой движок и модель соответствуют одному выбранному опыту? |
| Квантовые расчёты | Quantum ESPRESSO, CP2K, VASP | Какие свойства требуют этого метода, какой эталон и права? |
| Потенциалы и ML | OpenKIM, MACE, MatGL/CHGNet/M3GNet, MatterSim, FAIRChem/UMA | Область обучения, модельная ошибка, совместимость энергии и лицензии весов |
| Генерация/поиск структур | MatterGen, USPEX, AIRSS | Какие классы структур поддерживаются и как проверяются кандидаты? |
| Данные материалов | Materials Project, NOMAD, JARVIS, Materials Cloud, OPTIMADE, MaterialsMine | Доступ, права, происхождение и сопоставимость свойств |
| Active learning | DP-GEN и DeepModeling | Применимость цикла explore → select → label → train к выбранной задаче |
| Электронный транспорт | QuantumATK, nextnano | Доступность подходящей DFT/NEGF/semiconductor-модели для узкого устройства |
| Виртуальная микроскопия | abTEM | Какие наблюдения реально сопоставимы с доступным экспериментом? |
| ДНК-дизайн и альтернативы | caDNAno, MagicDNA, CanDO, MrDNA, ENSnano, DNAforge | Поддержка гибких соединений, excluded volume, входов и конкретного benchmark |
| Веб-интерфейс | AiiDAlab, nanoHUB | Можно ли переиспользовать UI вместо собственной платформы? |

Названия сохранены как список возможных исследований. Не предполагается подключить всё это к NL4. Проверенные общие входы ASE и OpenKIM: [S12 и S14](SOURCES.md).

## Коммерческие и внешние ориентиры

Microsoft Discovery, Matlantis, Citrine VirtualLab, Mat3ra, Schrödinger Materials Science/Bunsen, nanoHUB, NIST JARVIS и проекты Autonomous Formulation Lab сохраняются как ориентиры для изучения интерфейсов, workflows и автономных циклов.

Ранее обсуждавшиеся оценки зрелости, числа поддерживаемых элементов, названия последних релизов, даты GA, цены и обещания ускорения здесь **не подтверждаются и не становятся архитектурными основаниями**. До реального выбора требуется отдельная проверка первичной документации, доступа и экспортируемости результатов.

## Выбор зависимости

Требуются конкретный сценарий, маленький исполняемый пример, границы применимости, поддерживаемые входы, версия, лицензии кода/весов/данных, стоимость и возможность выгрузки evidence. Выбор одного хорошего адаптера предпочтительнее десятка недоказанных интеграций.
