# S17 R3 — Source Gaps: точные недостающие данные и следующие действия

Work Order: `WO-PREP-S17-R3` (execution `EX-PREP-S17-R3`). Дата: 2026-10-18.
Дополняет: [S17_R3_INTERFACE_AUDIT.md](S17_R3_INTERFACE_AUDIT.md).

Каждый гэп — конкретный отсутствующий вход с указанием, что он блокирует и каким
действием закрывается. Machine-readable статусы: `UNKNOWN`, `NOT_RECONSTRUCTED`,
`BLOCKED_SOURCE`.

## G1 — Follower structure (главный блокер сборки)

- **Отсутствует:** topology (.top), configuration (.dat) и caDNAno/scadnano design
  follower-юнита F (а также F-soft-hinge, F-ss-hinge).
- **Проверенные поверхности:** Nanobase 196 (12-файловый набор — только движок),
  Zenodo 8248808 (полные CD-перечисления 4 архивов, 2,324 записи — нет ни одного
  driver/follower каталога; receipt EX-PREP-S17-R2), `sulcgroup/hinges` @ `7c8b04a6`
  (только обработанные угловые ряды `driver_*/follower_*_data.txt`),
  supplementary (follower задан только ODN-списками Dataset S1).
- **Блокирует:** `SOURCE_VERIFIED` статическую сборку S17 D–F
  (текущий вердикт `NOT_RECONSTRUCTED`), любую оxDNA-постановку с follower.
- **Закрытие:** запрос авторам (см. §5 аудита; отправка — только с разрешения
  владельца) на публикацию design-файлов follower; или независимая реконструкция
  из Dataset S1 + M13 routing — отдельный WO с собственным evidence, не R3.

## G2 — Nucleotide-index anchors connecting ODN в nNE.top

- **Отсутствует:** соответствие «connecting ODN → particle index в nNE.top».
- **Причина:** все pinned-топологии несут placeholder-последовательности (R2);
  `NE_halo_dsDNA.json` (R1 pin) — дизайн БЕЗ D–F оверхэнгов (проверено: ни один
  из 10 overhang-сегментов не встречается в файле).
- **Блокирует:** объявление портов `connection_capable=true`, координатную
  привязку интерфейса, геометрическую проверку контакта на реальных входах.
- **Закрытие:** caDNAno-файл nNE с connecting ODN от авторов, либо
  scaffold-coordinate map; после этого индексы восстанавливаются детерминированно
  средствами `s17_index_map`.

## G3 — Per-ODN helix/arm assignment

- **Статус:** `INFERRED_CANDIDATE` — читается только с bitmap Suppl. Fig. 5a
  (helices 0–17; «flip upside down» для стыковки).
- **Блокирует:** точную ориентацию портов и 3D-проверку «flip»-преобразования.
- **Закрытие:** машиночитаемая таблица от авторов; либо ручная оцифровка рисунка
  с явным статусом `INFERRED_CANDIDATE` и независимой перепроверкой.

## G4 — Точная 3D-ориентация портов

- **Статус:** `UNKNOWN` (качественное текстовое описание F9 есть, координат нет).
- **Блокирует:** статическую геометрию контакта для реальной пары
  (в R3 геометрия реализована и проверена только на синтетической паре).
- **Закрытие:** вместе с G2/G3 — из design-файлов.

## G5 — Термодинамика/кинетика 10 пар гибридизации

- **Статус:** `UNKNOWN` (не опубликованы; LNA-позиции известны, но не параметры).
- **Блокирует:** предсказание yield D–F дуплекса (60% ± 20% остаётся
  экспериментальным фактом, не моделью).
- **Закрытие:** вне claim-потолка PREP; отдельный научный WO после NL6/E5
  разблокировки. Не является блокером статической сборки.

## G6 — Molecule-level связь «trap ↔ полимераза» с оверхэнгами в одном дизайне

- **Статус:** force-пары (8694/7374 для nNE) `SOURCE_CONFIRMED` (R2); их
  координатная связь с оверхэнгами — та же зависимость от G2.
- **Закрытие:** совместное закрытие с G2.

## Что НЕ является гэпом (уже закрыто)

- Механизм соединения D–F (гибридизация 10 пар) — `SOURCE_CONFIRMED`.
- Все 20 connecting-последовательностей и их паросочетание —
  `SOURCE_CONFIRMED` + машино-проверено (recipe JSON).
- Экспериментальные ограничения результата (yield, углы, скорости) —
  `SOURCE_CONFIRMED`.
- Наличие/отсутствие bridge-ODN для D–F: соединение реализовано оверхэнгами
  connecting-ODN-стейплов (F10 `INFERRED_CANDIDATE` на «при сборке»), внутренний
  dsDNA-t/полимеразный интерфейс — отдельная поверхность (R2).

## Приоритетный порядок действий

1. Draft PR R3 → fresh Reviewer + exact-head Verifier → Human Gate merge (R2
   сначала, затем перенос R3 на `main`).
2. Owner approval на отправку вопросов авторам (G1–G4).
3. После получения design-файлов: отдельный bounded WO на
   `SOURCE_VERIFIED_STATIC_ASSEMBLY` реальной пары (индексация G2 → порты →
   геометрия → сборка → независимая проверка). Никаких научных прогонов до
   разблокировки NL5 acceptance + U1/R2.
