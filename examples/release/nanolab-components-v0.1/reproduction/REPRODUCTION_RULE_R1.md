# REPRODUCTION_RULE_R1 — правило сравнения независимой кампании воспроизведения

Статус: **ПРЕДРЕГИСТРИРОВАНО / FROZEN**. Правило заморожено этим коммитом — **до
запуска любых новых симуляций NL5-001-C** и до просмотра любых новых данных.
Изменение правила после просмотра результатов C запрещено; изменение = новая
ревизия правила (R2) + независимый review, никогда не правка задним числом.

Основание: Fresh Review R1 для NL5-001-B, находка **F-B3**
(`docs/evidence/NL5-001-B/FRESH_REVIEW_R1.md`, repair map
`docs/evidence/NL5-001-B/REPAIR_MAP_R1.md`, R1). Правило заменяет прежнюю
формулировку «pooled median должен попасть в bootstrap CI95 карточки, иначе
`REPRODUCTION_MISMATCH`», которая методологически неверна и в карточках v0.1
больше не используется.

## 1. Статистическая ошибка, которую фиксирует правило

Bootstrap CI95 публикуемой pooled median — это характеристика **неопределённости
самой исходной оценки** (resampling её собственных кадров). Это НЕ предикционный
интервал для новой независимой кампании: между-репличная вариативность materially
шире. Публикуемый 0b-evidence это прямо демонстрирует:

```text
pooled median 0b:            65.976921401 deg
pooled bootstrap CI95:       [65.674963662, 66.318271836]  (ширина ~0.64 deg)
репличные медианы 0b:        65.095434789 / 65.708669763 / 67.236579608
                             (размах ~2.14 deg)
```

Две из трёх **собственных** реплик исходной кампании лежат ВНЕ её pooled CI95.
При старом правиле честная одиночная реплика классифицировалась бы как
`REPRODUCTION_MISMATCH`. Поэтому CI95 исходной оценки запрещено использовать как
полосу допуска для воспроизведения; он остаётся в карточке только как публикуемая
характеристика точности исходной оценки.

## 2. Замороженные определения

### 2.1 Реплика (candidate)

Реплика новой кампании — независимый прогон oxDNA по протоколу карточки
(`protocol_pins`, digest-гейты `source_provenance`), прошедший:

1. digest-гейт входов (size + blob_sha1 обязательны; sha256 — согласно
   `sha256_status`);
2. кадровые гейты §4 `E2_PROTO_R1` (long_bond / pairs_fraction_v2 /
   displacement / energy drift).

Реплика в отчёте кампании несёт: `replica_id`, `median_deg` (медиана угла по
валидным кадрам в заявленном окне карточки), `frames_valid`, `frames_total`,
`gates_passed` (boolean). Реплика с `gates_passed: false` исключается из
статистики и перечисляется в отчёте вердикта (исключения не прячутся).

### 2.2 Статистика кампании

`M_new` = медиана пер-репличных медиан валидных реплик (по возрастанию; при
нечётном J — средняя, при чётном J — среднее двух средних). Обе стороны
сравнения — пер-репличные медианы: и референсная полоса, и статистика новой
кампании построены на одной и той же статистике уровня реплики.

### 2.3 Референсная полоса (из карточки, без подгоняемых параметров)

По пер-репличным медианам исходной кампании, опубликованным в карточке
(`measured_observables[...].distribution.per_replica_median_deg`, k значений):

```text
band = [min(m_i), max(m_i)],  k >= 2
```

Никаких свободных параметров правило не содержит.

### 2.4 Структура новой кампании

`J_min = 3` валидных реплики (зеркалит R_confirm = 3 исходного протокола E2).
Семена новой кампании — новые, не переиспользуют семена исходной (иначе это не
независимая кампания). Окно анализа — заявленное в карточке
(`hinge_angle_common_window_150k` / `hinge_angle_confirmatory_200k`).

## 3. Вердикты (исчерпывающий набор)

| Вердикт | Условие |
|---|---|
| `TECHNICAL_FAILURE` | Отчёт кампании отсутствует/пуст; ОТКАЗ инфраструктуры/digest-гейта; ВСЕ реплики провалили гейты. Технический исход, не научный; кампания повторяется, результат НЕ считается научным несоответствием. |
| `INCONCLUSIVE` | `1 <= J_valid < 3` (недостаточно валидных реплик), или в референсной карточке < 2 пер-репличных медиан. Явный не-PASS: власти подтвердить или опровергнуть воспроизведение недостаточно. |
| `REPRODUCTION_MATCH` | Все предусловия выполнены и `band_min <= M_new <= band_max`. |
| `REPRODUCTION_MISMATCH` | Все предусловия выполнены и `M_new` вне `band`. Научный исход, сохраняется durable как есть. |

Порядок проверки жёсткий: сначала `TECHNICAL_FAILURE`, затем `INCONCLUSIVE`,
только потом MATCH/MISMATCH. Отсутствие проверки — не PASS (правило
DATA_CONTRACTS). Для карточек `NOT_MEASURED` (74b) воспроизведение не определено
— `n/a` (сравнивать нечего; попытка «воспроизвести» отсутствующие значения
запрещена).

## 4. Машиночитаемый интерфейс

Нормативный исполнитель — `scripts/release/reproduction.py` (stdlib-only,
детерминированный, `evaluate(card, candidate_report)`). Clean-room исполнитель —
`reproduction/reproduce.py evaluate` внутри пакета (та же замороженная логика и
константы; conformance-тест требует совпадения вердиктов на одних и тех же
входах). Отчёт кандидата:

```json
{
  "rule": "REPRODUCTION_RULE_R1",
  "card": "dna_hinge/0b",
  "window_steps": 150000,
  "replicas": [
    {"replica_id": "C-NEW-001", "median_deg": 65.9, "frames_valid": 37,
     "frames_total": 37, "gates_passed": true}
  ]
}
```

Вердикт-отчёт дополнительно всегда содержит: `candidate_statistic`,
`reference_band` (min/max/k), референсные pooled median и CI95 (информационно) и
флаг `ci95_is_not_acceptance_band: true`.

## 5. Контрольные случаи (обязательные тесты)

1. Контроль воспроизводимости: кампания, чья статистика попадает в референсную
   полосу реальной карточки 0b → `REPRODUCTION_MATCH`.
2. Анти-F-B3 регрессия: значение ВНЕ pooled CI95 карточки, но ВНЕ-полосы-нет
   (внутри `[min, max]` пер-репличных медиан) → `REPRODUCTION_MATCH`, а не
   mismatch.
3. Вне полосы → `REPRODUCTION_MISMATCH`.
4. `J_valid = 2` → `INCONCLUSIVE`; реплики с проваленными гейтами исключаются и
   видны в отчёте.
5. Все реплики с проваленными гейтами → `TECHNICAL_FAILURE`, не научный mismatch.

## 6. Применение к NL5-001-C / NL5-002

Clean-room кампания NL5-001-C сравнивает свои результаты с карточками v0.1
ТОЛЬКО по этому правилу (исполнитель — `reproduce.py evaluate` из пакета).
Сравнение «вручную по CI95» запрещено. Любая модификация порогов/полосы после
просмотра данных C = нарушение протокола; требуется новая ревизия правила,
публикуемая до следующей кампании.
