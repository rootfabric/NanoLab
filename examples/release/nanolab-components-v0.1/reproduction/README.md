# Reproduction interface (v0.1 contract)

Пакет воспроизводится ИЗ ПАКЕТА, без внутренних знаний авторского репозитория
(правило fresh environment, NL5-002).

## Порядок

1. `python3 reproduction/reproduce.py verify` — контроль целостности пакета
   (перерасчёт SHA-256 и размеров по `RELEASE_MANIFEST.json`).
2. `python3 reproduction/reproduce.py plan` — план воспроизведения по карточкам:
   engine pins, шаги, expected-значения, права.
3. Внешний исполнитель сам выполняет шаги карточки в свежей среде:
   download-on-run upstream-входов по exact pinned commit с digest-гейтом
   (см. `RIGHTS.json` и `rights` секции карточек), сборка входов, прогоны
   движка, анализ. `durable_cache` запрещён.
4. Сравнение кампании с карточкой — ТОЛЬКО по замороженному правилу
   `REPRODUCTION_RULE_R1` (копия: `reproduction/REPRODUCTION_RULE_R1.md`):

   ```text
   python3 reproduction/reproduce.py evaluate <card.json> <campaign-report.json>
   ```

   Полоса допуска — `[min, max]` пер-репличных медиан карточки (k >= 2),
   статистика кампании — медиана пер-репличных медиан >= 3 валидных реплик.
   Вердикты: `REPRODUCTION_MATCH`, `REPRODUCTION_MISMATCH`,
   `INCONCLUSIVE` (меньше трёх валидных реплик — явный не-PASS),
   `TECHNICAL_FAILURE` (технический отказ, не научный mismatch).
   Pooled bootstrap CI95 исходной оценки — характеристика точности исходной
   оценки и **не** является полосой допуска для новой кампании.
   `REPRODUCTION_MISMATCH` — честный научный исход, сохраняется; не PASS и
   не скрывается.

## Важно

* `NOT_MEASURED`-карточки (например, `74b` в этом примере) не содержат
  значений для воспроизведения — выдумывать их запрещено (`evaluate` для них
  не определён).
* В v0.1 этот helper не скачивает входы и не запускает физический движок
  самостоятельно; исполнение — ответственность внешнего воспроизводителя по
  шагам карточки. Автоматизация исполнения — отдельная задача (NL5-001-C).
* Helper stdlib-only: никаких сторонних зависимостей.
* Пороги правила `REPRODUCTION_RULE_R1` заморожены до наблюдения новых данных;
  изменение правила = новая ревизия, никогда не правка задним числом.
